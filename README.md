# نظام إدارة الأصناف والعُهد

**منصّة داخلية تُدخل الصنف من باب واحد، وتنقله بتوقيع، وتُثبت أين هو ومَن يحمله.**

## ما الذي يفعله

نظام إدارة أصول مُكيَّف على إجراءات جهة حكومية: الصنف لا يدخل المخزون إلا عبر
**نموذج استلام موقَّع**، ولا ينتقل إلى شخص إلا عبر **محضر تسليم يوقّعه طرفان**.

الفكرة الحاكمة: **التوقيع الثاني هو ما ينقل العهدة** — لا الضغطة على زرّ.

### القرارات التي تميّزه

| القرار                            | لماذا                                                                                                    |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **باب دخول واحد**                 | `/assets/new` و`/assets/import` مغلقان. كل صنف يدخل عبر `GoodsReceipt` — فلا مخزون بلا مورّد وسعر ومستند |
| **لا يوقّع شخص واحد نصفَي محضر**  | حتى لو ملك الصلاحيتين. مَن هو الطرف المقابل يأخذ خانته ويرجع                                             |
| **الفحص يتكرّر عند التوقيع**      | المحضر قد يُوقَّع بعد أيام؛ المخزون يُعاد فحصه داخل الترانزاكشن قبل تطبيق الأثر                          |
| **صلاحيات بقائمة سماح**           | الدور غير المسجَّل **يُحجب افتراضياً** — لا فحص سلبي (`!== SELF_SERVICE`)                                |
| **الأصل ينتقل بالعهدة لا بالحجز** | لا حجز زمني: `from`/`to` لا معنى لهما هنا                                                                |
| **المبالغ هللات صحيحة**           | لا `float` في المال                                                                                      |

## التشغيل المحلي

يحتاج **Node ≥ 22.20**، **pnpm**، و**Docker Desktop** يعمل.

```bash
pnpm install
cp .env.example .env          # املأ القيم
supabase start                # قاعدة البيانات والمصادقة محلياً
pnpm webapp:setup             # توليد عميل Prisma + تطبيق الترحيلات
pnpm webapp:seed:org          # حسابات تجريبية (كلمة المرور تُطبع مرة واحدة)
pnpm webapp:dev               # http://localhost:3000
```

### أوامر يومية

```bash
pnpm webapp:validate      # الأنواع + lint + الاختبارات (قبل أي commit)
pnpm webapp:test -- --run # الاختبارات مرة واحدة (بلا وضع المراقبة)
pnpm webapp:build         # بناء إنتاج
pnpm db:prepare-migration # ترحيل جديد بعد تعديل المخطط
pnpm docs:dev             # موقع التوثيق
```

> **تحذير:** `pnpm db:reset` يمسح كل بيانات قاعدة التطوير. يُعيد البذر تلقائياً
> بعده، لكن ما مُسح لا يعود.

## المنهجية

المستودع يحمل سجلّاً هندسياً مفصّلاً في [`CLAUDE.md`](./CLAUDE.md): قرارات
التصميم، والمزالق التي كلّفت وقتاً في التشخيص **مكتوبة بعَرَضها الظاهر لا
بسببها التقني وحده** — لأن مَن يصل إليها لاحقاً يصل ومعه العَرَض لا السبب.

أمثلة موثّقة بصدق، بما فيها النتائج السلبية:

- **`include` في Prisma ليس محميّاً بالمترجم عبر غلاف عامّ** — اسم علاقة محذوفة
  مرّ من typecheck و٢٥٠٠ اختبار وبناء إنتاج، وانكسر وقت التشغيل. جُرِّب تشديد
  النوع **وفشل**، فوُثِّق أنه طريق مسدود وبُني اختبار يمشي على `Prisma.dmmf` بدلاً منه.
- **المترجم لا يرى داخل `Prisma.sql`** — وصلة محذوفة بقي اسمها المستعار في
  `GROUP BY` فانكسرت صفحة الأصناف لبعض المستخدمين فقط (وضع الفهرس لكل مستخدم).
  الحارس الآن يكنس ٣٢ شكل استعلام لا شكلاً واحداً.
- **البحث النصّي خذل مرتين** في تتبّع كود ميت؛ ما كشف الحقيقة تشغيل الاستعلامات
  على قاعدة حقيقية.
