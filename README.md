# نظام إدارة الأصناف والعُهد

### هيئة تطوير المنطقة الشرقية

**منصّة داخلية تُدخل الصنف من باب واحد، وتنقله بتوقيع، وتعرف في كل لحظة من يحمله.**
عربية بالكامل · تعمل على البنية التحتية للهيئة · بلا اشتراكات.

## نظرة عامة

يجيب النظام عن ثلاثة أسئلة تُسأل يومياً ولا يملك أحد إجابتها موثّقة: **ماذا نملك؟ أين هو؟ ومن يتحمّل مسؤوليته الآن؟**

وهو ليس منصّة جرد عامة عُرِّبت، بل نظام مبنيّ حول **مستندات الهيئة الورقية نفسها**: نموذجا الاستلام (٢ و٣) هما الباب الوحيد لدخول الأصناف، ومحضر التسليم هو ما ينقل العهدة. الشاشة تُنتج ما كان يُكتب باليد، لا شيئاً موازياً له.

---

## ما يميّز هذا النظام

### 🔒 لا تتحرّك عهدة بلا توقيعَين

كل انتقال — من المستودع إلى إدارة، ومن الإدارة إلى موظف — ينشئ **محضراً موقّعاً** (`EPDA-HO-…`). والتوقيع الثاني هو ما ينقل العهدة فعلاً، داخل نفس المعاملة التي تُكمل المحضر: لا توجد حالة «مكتمل ولم يُطبَّق» يمكن استغلالها.

ويستحيل أن يوقّع شخص واحد نصفَي محضر، **ولو ملك الصلاحيتين معاً** — الطرف المقابل المسمّى يأخذ خانته وحدها، ويحرس القاعدةَ اختبارٌ صريح. محضرٌ يوقّعه طرف واحد لا يشهد عليه أحد.

### 🚪 باب واحد لدخول المخزون

الأصناف تدخل عبر `/receipts` **فقط**. مسارا الإنشاء المباشر والاستيراد صارا تحويلاً — في الـ`loader` **والـ`action`** معاً، فحتى إعادة إرسال نموذج من تبويب قديم لا تفتح باباً ثانياً.

النتيجة: لكل صنف في النظام مستندٌ يشرح كيف وصل، ومورّدٌ، وسعرٌ، ورقم أمر شراء. ولا يوجد مخزون «ظهر من العدم».

### 🏢 الإدارات بيانات لا كود

المرافق وتقنية المعلومات إدارتان مستقبِلتان، ودورهما **واحد عامّ** (`DEPARTMENT`) مع تمييز بالبيانات. إضافة إدارة ثالثة = صفّ جديد وربط مستخدم به — **بلا ترحيل ولا تعديل على مصفوفة الصلاحيات**.

### 📦 الكمية تنتقل جزئياً

سطر توريدة من ٣٠ قلماً هو صنف واحد كميته ٣٠. تستلمه الإدارة كاملاً، ثم تسلّم ١٠ لموظف و٢٠ لآخر — وكل تسليم بمحضره وكميته. الحساب محروس: لا يُصرف ما لا يملكه المُسلِّم، ولا يُقلب الصنف «متاحاً» وكميةٌ منه ما زالت خارجة.

### 🧭 الصلاحيات تُفحص فحصاً إيجابياً

النمط الشائع (`إن لم يكن موظفاً بسيطاً فهو مسؤول`) يمنح كل دور يُضاف لاحقاً صلاحيات مسؤول **بصمت**. هنا العكس: قائمة سماح مركزية، **والدور غير المسجَّل يُحجب افتراضياً** — ويحرس هذه الخاصية اختبارٌ قائم بذاته.

### 🇸🇦 عربي أولاً لا معرَّب لاحقاً

العربية هي الافتراضية باتجاه RTL، والتخطيط يتبع اللغة عبر الخصائص المنطقية لا الفيزيائية. ومسار الاستلام يستعمل **ألفاظ النموذجين الرسميين حرفياً** («مأمور عهدة ساحة الاستلام»، «حد الرسملة») — لأن ترجمتها الحرفية تُنتج مستنداً لا يطابق الورقة التي يُعيد إنتاجها.

## سير العمل

```
        ┌──────────────┐   نموذج ٢ / ٣ موقّع
        │  المستودعات  │ ──────────────────────► الصنف يدخل النظام  (PENDING)
        └──────┬───────┘
               │ اعتماد
               ▼
          (READY)  ──── محضر دفعة برقم أمر الشراء ────►  ┌─────────────┐
                              توقيعان                      │   الإدارة    │
                                                          │ مرافق / IT  │
                                                          └──────┬──────┘
                                                                 │ محضر تسليم
                                                                 │  توقيعان
                                                                 ▼
                                                            ┌─────────┐
                                                            │ الموظف  │
                                                            └─────────┘
```

الإدارة **تبادر بالتسليم** — لا يقدّم الموظف طلباً. لكن توقيعه إلزامي، فحساباته باقية لهذا الغرض ولرؤية ما في عهدته.

## الأدوار

| الدور               | enum                    | ما يملكه                                            |
| ------------------- | ----------------------- | --------------------------------------------------- |
| **تقنية المعلومات** | `OWNER` + `DEPARTMENT`  | صلاحيات كاملة — وهي أيضاً **إدارة مستقبِلة**        |
| **المستودعات**      | `WAREHOUSE`             | يضيف الصنف، يعتمده، ويسلّمه للإدارات دفعةً واحدة    |
| **المالية**         | `FINANCE`               | تعدّل بيانات الصنف والترميز — **لا تضيف ولا تعتمد** |
| **المخزون**         | `INVENTORY`             | يراقب ويعلّق للمراجعة — **لا يقرّر**                |
| **الإدارة**         | `DEPARTMENT`            | تستلم دفعةً وتسلّم موظفيها — **لا تنشئ ولا تعتمد**  |
| **الموظف**          | `SELF_SERVICE` / `BASE` | يستلم عهدةً ويوقّع                                  |

الفصل مقصود: `approve` (البتّ) و `hold` (التعليق للمراجعة) إجراءان مختلفان لا يجتمعان في دور واحد — المخزون يعلّق ولا يقرّر، والمستودعات تقرّر ولا تعلّق.

## القدرات

**الاستلام والترميز** — نموذجا استلام مطابقان للورق، **قالب إكسل** للتوريدات الكبيرة، تصنيف تلقائي أصل/مادة بحدّ الرسملة، وترميز مالي بطابور عمل للمالية.

**أوامر الشراء** — مشتقّة من النماذج بلا جدول جديد: كل ما وصل تحت رقم أمر واحد في شاشة واحدة، مع طباعة أفقية للمستند.

**العُهد والمحاضر** — تسليم فردي وجماعي، توقيع حضوري أو عن بُعد، ونقل مباشر من الإدارة للموظف بلا رجوع للمستودع.

**الترميز والمسح** — رموز QR وباركود بشعار الهيئة، ومسح من الجوال لعرض الصنف أو تسليمه.

**التنظيم والبحث** — بحث نصي كامل، فلاتر متقدّمة بقوالب محفوظة، ومواقع هرمية (مبنى ← دور ← غرفة ← رف).

**العمليات** — الجرد الميداني، تذكيرات الصيانة والضمان، وتقارير المخزون والعُهد والتوزيع.

**الحوكمة** — عزل كامل بين مساحات العمل، وسجل تدقيق وملاحظات على كل صنف.

## التشغيل المحلي

### المتطلبات

- [Node.js](https://nodejs.org/) **22.20.0** فأعلى
- [pnpm](https://pnpm.io/) **9.15.9**
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — يجب أن يكون **شغّالاً** قبل البدء
- [Supabase CLI](https://supabase.com/docs/guides/cli)

### خطوات التشغيل

```bash
# 1. تثبيت الاعتماديات
pnpm install

# 2. تشغيل Supabase محليًا — قاعدة بيانات ومصادقة وتخزين بلا خدمات خارجية
supabase start

# 3. إعداد ملف البيئة في جذر المستودع (وليس داخل apps/webapp)
cp .env.example .env
# املأ القيم من مخرجات supabase start — انظر الجدول أدناه

# 4. توليد عميل Prisma وتطبيق الترحيلات
pnpm webapp:setup

# 5. إنشاء الحسابات التجريبية
pnpm webapp:seed:epda

# 6. تشغيل خادم التطوير
pnpm webapp:dev
```

يعمل التطبيق على **`https://localhost:3000`** (خادم التطوير يستخدم HTTPS بشهادات محلية).

> ⚠️ **بعد أي تعديل على `schema.prisma`:** شغّل `pnpm db:deploy-migration` ثم امسح `apps/webapp/node_modules/.vite` **وأعد تشغيل الخادم**. Vite يحتفظ بنسخة مُحسَّنة من عميل Prisma، فتبقى الأعمدة الجديدة مجهولة عنده حتى بعد التوليد.

### متغيّرات البيئة المطلوبة

ملف `.env` في **جذر المستودع**، ومنه تقرأ Vite و Prisma وجميع أوامر `db:*`.

| المتغيّر                | المصدر                                             |
| ----------------------- | -------------------------------------------------- |
| `DATABASE_URL`          | من مخرجات `supabase start` (مع pooler)             |
| `DIRECT_URL`            | من مخرجات `supabase start` (اتصال مباشر للترحيلات) |
| `SUPABASE_URL`          | من مخرجات `supabase start` (API URL)               |
| `SUPABASE_ANON_PUBLIC`  | مفتاح `anon` من مخرجات `supabase start`            |
| `SUPABASE_SERVICE_ROLE` | مفتاح `service_role` من مخرجات `supabase start`    |
| `SESSION_SECRET`        | نص عشوائي — `openssl rand -base64 32`              |
| `SERVER_URL`            | `https://localhost:3000` للتطوير المحلي            |
| `DISABLE_SIGNUP`        | `"true"` — تعطيل التسجيل الذاتي                    |
| `DISABLE_SSO`           | `"true"` حتى تفعيل Azure Entra                     |

> **تنبيه أمني:** `supabase start` يطبع مفاتيح `anon` و `service_role` المحلية — انسخها إلى `.env`. لا تضع أبدًا مفاتيح الإنتاج في Git؛ `.env` مستثنى في `.gitignore` وعليه أن يبقى كذلك.

لا حساب منفصل لـIT عمداً: الهيئة تُشغّل تقنية المعلومات على حساب الأدمن نفسه، فيحمل الدورين — `OWNER` لإدارة النظام و `DEPARTMENT` ليستلم دفعات مكتبه ويوقّعها.

## الأوامر المرجعية

### التطوير

| الأمر               | الوصف                        |
| ------------------- | ---------------------------- |
| `pnpm webapp:dev`   | خادم التطوير على المنفذ 3000 |
| `pnpm webapp:build` | بناء الإنتاج                 |
| `pnpm webapp:start` | تشغيل نسخة الإنتاج محليًا    |
| `pnpm docs:dev`     | موقع التوثيق على المنفذ 5173 |

### الجودة

| الأمر                       | الوصف                                    |
| --------------------------- | ---------------------------------------- |
| `pnpm webapp:validate`      | **التحقق الشامل — يُشغّل قبل كل commit** |
| `pnpm webapp:test -- --run` | اختبارات الوحدة (استخدم `--run` دائمًا)  |
| `pnpm webapp:lint`          | فحص ESLint                               |
| `pnpm turbo typecheck`      | فحص أنواع TypeScript                     |
| `pnpm webapp:doctor`        | فحص صحة React للواجهة                    |

> **مهم:** استخدم `--run` دائمًا عند تشغيل الاختبارات يدويًا. بدونه يعمل Vitest في وضع المراقبة ويستهلك ذاكرة مفرطة. ولا تشغّل أكثر من عملية اختبار بالتوازي.

### قاعدة البيانات

| الأمر                       | الوصف                               |
| --------------------------- | ----------------------------------- |
| `pnpm db:generate`          | توليد عميل Prisma بعد تعديل السكيما |
| `pnpm db:prepare-migration` | إنشاء ترحيل جديد                    |
| `pnpm db:deploy-migration`  | تطبيق الترحيلات وإعادة توليد العميل |
| `pnpm db:reset`             | **إعادة تعيين — يمسح كل البيانات**  |

> ⚠️ **ولّد الترحيلات دائمًا بـ`--create-only` واقرأ الـSQL سطرًا سطرًا.** بريزما تُدرج في الترحيل حذفَ فهارس ومفاتيح أجنبية أُنشئت يدويًا ولم تُعلَن في السكيما — عن جداول لم تلمسها أصلًا. التفاصيل في [`CLAUDE.md`](./CLAUDE.md).

## معايير التطوير

قبل أي مساهمة، راجع [`CLAUDE.md`](./CLAUDE.md) — يوثّق الاتفاقيات الإلزامية والمزالق التي كلّفت وقتًا:

- **التعريب:** كل نص ظاهر يمر عبر `t()` ويُضاف إلى `ar.json` و `en.json` معًا. الخصائص المنطقية (`ms-`/`me-`/`text-start`) بدل الفيزيائية — عدا قوالب البريد و PDF.
- **التوثيق:** كل ملف وكل تصدير عام يحمل JSDoc يشرح الغرض والمعاملات والأخطاء، و«لماذا» لا «ماذا».
- **الأنواع:** ممنوع `any` كاختصار — `unknown` مع تضييق النوع إن كان الشكل ديناميكيًا فعلًا.
- **النماذج:** أخطاء التحقق من الخادم تُعرض دائمًا كطبقة احتياطية للتحقق في المتصفح.
- **الأزرار:** كل `<Button>` يُصيَّر كـ`<button>` يحتاج `type` صريحة.
- **الاختبارات:** موجّهة بالسلوك، وكل mock مصحوب بتعليق `// why:` يبرّره.
- **الرسائل:** [Conventional Commits](https://www.conventionalcommits.org/)، وكل سطر في المتن ≤ 100 حرف.

قبل كل commit: `pnpm webapp:validate`

- يجب الإبقاء على إشعار الترخيص وعلى نسبة العمل الأصلي في أي توزيع لاحق.

الشكر لفريق Shelf.nu ولمجتمع المساهمين على القاعدة التي بُني عليها هذا العمل.
