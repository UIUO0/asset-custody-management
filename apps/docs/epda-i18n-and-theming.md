# التعريب والمظهر (i18n / RTL)

نظام هيئة تطوير المنطقة الشرقية يدعم العربية والإنجليزية مع تبديل فوري،
واتجاه تخطيط (RTL/LTR) يتبع اللغة تلقائياً. **المظهر فاتح فقط.**

## البنية

| الملف                                           | الغرض                                              |
| ----------------------------------------------- | -------------------------------------------------- |
| `app/i18n/config.ts`                            | اللغات المدعومة، الاتجاه لكل لغة، إعدادات i18next  |
| `app/i18n/i18n.server.ts`                       | كشف اللغة من الكوكي/المتصفح + إنشاء نسخة لكل طلب   |
| `app/i18n/locales/ar.json` و `en.json`          | ملفات الترجمة                                      |
| `app/utils/theme.ts`                            | تفضيل المظهر — **بلا مستوردين حالياً**، انظر أدناه |
| `app/hooks/use-direction.ts`                    | اتجاه النص للمكوّنات التي تحتاج جهة فيزيائية       |
| `app/components/layout/appearance-switcher.tsx` | مبدّل اللغة (لا مظهر)                              |
| `app/routes/api+/preferences.tsx`               | نقطة حفظ تفضيل اللغة (كوكي)                        |

## إضافة نص مترجم

```tsx
import { useTranslation } from "react-i18next";

function MyComponent() {
  const { t } = useTranslation();
  return <h2>{t("assets.title")}</h2>;
}
```

أضف المفتاح في **كلا** الملفين `ar.json` و `en.json`.

داخل `loader` أو `action` (لا يعمل فيها `useTranslation`):

```ts
const i18n = await createI18nInstance(getLocale(request));
const title = i18n.t("auth.loginTitle");
```

## قواعد الاتجاه (RTL)

التخطيط ينعكس تلقائياً لأن المشروع يستخدم **الخصائص المنطقية** بدل الفيزيائية:

| ❌ لا تستخدم      | ✅ استخدم        |
| ----------------- | ---------------- |
| `ml-4` / `mr-4`   | `ms-4` / `me-4`  |
| `pl-2` / `pr-2`   | `ps-2` / `pe-2`  |
| `text-left/right` | `text-start/end` |

**استثناء:** قوالب الإيميل و PDF تبقى بالخصائص الفيزيائية — عملاء البريد
ومولّد PDF لا يدعمون الخصائص المنطقية.

للمكوّنات التي تفرض جهة فيزيائية (مثل `side` في Radix) استخدم:

```tsx
import { useInlineEndSide } from "~/hooks/use-direction";

const side = useInlineEndSide(); // "left" بالعربي، "right" بالإنجليزي
<DropdownMenuContent side={side} />;
```

## الوضع الداكن — مُعطَّل، والبنية باقية

**الحالة الفعلية:** الوضع الداكن أُزيل من الواجهة في `72f86d1`. لا مبدّل مظهر
في `appearance-switcher.tsx`، و `preferences.tsx` يتجاهل أي حقل مظهر صراحةً،
ولا أحد يضيف الفئة `dark` إلى `<html>`. **المستخدم يرى الوضع الفاتح دائماً.**

**لكن البنية كاملة ولم تُحذف:**

| العنصر                          | الحالة                  |
| ------------------------------- | ----------------------- |
| كتلة `.dark` في `global.css`    | كاملة                   |
| `darkMode: "class"` في Tailwind | مفعّل                   |
| `app/utils/theme.ts`            | باقٍ — **بلا مستوردين** |
| `text-static-white` في ١٩ ملفاً | مستخدَم                 |

إعادة التفعيل تعني وصل هذه القطع لا إعادة بنائها. **لا تحذف أياً منها** لأن
أداة كـ knip ستقول إنها ميتة — هي معطَّلة لا ميتة، والفرق جوهري.

المظهر مبني على **متغيرات CSS** في `app/styles/global.css` يستهلكها
`tailwind.config.ts`، فكتلة `.dark` تعيد تلوين النظام **كاملاً** دون `dark:`
على كل مكوّن — لأن الكود يستخدم تدرّج الرمادي دلالياً (أرقام صغيرة للأسطح،
كبيرة للنصوص)، فقلب التدرّج ينتج ثيماً متماسكاً تلقائياً.

**قاعدة تبقى سارية:** `bg-white` سطحٌ ينقلب، أما النص أو الأيقونة فوق خلفية
ملوّنة فيستخدم `text-static-white` — رمز ثابت لا ينقلب. التزم بها في الكود
الجديد حتى يبقى خيار إعادة التفعيل قائماً بلا مراجعة ٧٨٠ ملفاً.

```tsx
// ❌ سينقلب على خلفية زرقاء إن أُعيد تفعيل الوضع الداكن
<button className="bg-primary-600 text-white">حفظ</button>

// ✅ يبقى أبيض دائماً
<button className="bg-primary-600 text-static-white">حفظ</button>
```

## إضافة لغة جديدة

1. أضف رمزها في `SUPPORTED_LOCALES` و `LOCALE_DIRECTION` و `LOCALE_LABEL`.
2. أنشئ `app/i18n/locales/<code>.json`.
3. سجّلها في `resources` داخل `config.ts`.

لا حاجة لأي تعديل آخر — المبدّل والاتجاه يشتقّان منها تلقائياً.
