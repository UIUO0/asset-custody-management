## الأدوات والأنماط المضافة

### `getFixedT(locale)` — للترجمة داخل loaders/actions

معرَّفة في `app/i18n/i18n.server.ts`. تُرجع دالة `t` مربوطة بلغة الطلب، مع
تخزين مؤقّت لنسخة i18next واحدة لكل لغة (آمنة تحت التزامن لأن اللغة ثابتة ولا
تحمل حالة الطلب).

```ts
import { getFixedT, getLocale } from "~/i18n/i18n.server";

export async function loader({ request }: LoaderFunctionArgs) {
  const t = await getFixedT(getLocale(request));
  return payload({ header: { title: t("assets.importTitle") } });
}
```

استخدمها للنصوص التي يضعها الـ loader في الحمولة: `header.title`،
`header.subHeading`، `searchFieldLabel`، `searchFieldTooltip`.

### نمط `meta`

`meta` تُنفَّذ خارج React، فتقرأ اللغة من الـ root loader:

```tsx
export const meta: MetaFunction = ({ matches }) => {
  const rootData = matches.find((m) => m.id === "root")?.data as
    | { locale?: string }
    | undefined;
  const resources = rootData?.locale === "en" ? en : ar;
  return [{ title: appendToMetaTitle(resources.bookings.manageAssetsTitle) }];
};
```

### الثوابت على مستوى الوحدة تخزّن **مفاتيح** لا نصوصاً

كثير من الملفات تُعرِّف مصفوفات إعداد على مستوى الوحدة (تعريفات أعمدة الجداول،
خيارات القوائم، إعدادات الحالات الفارغة). هذه لا يمكنها استدعاء `useTranslation`،
والقاعدة المتّبعة أن تخزّن **مفتاح i18n** ويحلّه المستهلك:

| الملف                                             | الحقل                          |
| ------------------------------------------------- | ------------------------------ |
| `reports/*-content.tsx`                           | `header` (يحلّه `ReportTable`) |
| `reports/report-empty-state.tsx`                  | `titleKey` / `descriptionKey`  |
| `reports/timeframe-picker.tsx`                    | `labelKey` / `shortLabelKey`   |
| `workspace/qr-id-display-preference-selector.tsx` | `labelKey` / `descriptionKey`  |
| `welcome/choose-purpose.tsx`                      | `helperKey` / `ctaLabelKey`    |
| `scanner/drawer/action-switcher.tsx`              | `ACTION_LABEL_KEYS`            |
| `kits.$kitId.assets.manage-assets.tsx`            | `labelKey`                     |

`ReportTable` يحلّ رؤوس الأعمدة تلقائياً: إن كان `columnDef.header` نصاً فهو
مفتاح ويُمرَّر إلى `t()`؛ وإن كان دالة فيُرسَم عبر `flexRender` كالمعتاد.

### الدوال المساعدة تأخذ `t` كمعامل

الدوال التي ليست مكوّنات ولا تستطيع استضافة hook تستقبل `t` كمعامل:
`assetLabelPresets` و`kitLabelPresets` و`getCopyByMode` و`resolveCopy` و
`buildWorkspaceDefaultSecondary` و`formatFilterSummary` و
`renderPendingIndividualAsset` و`renderPendingQtyAsset` و
`renderAlreadyReconciledAsset`.

### مُعالِجات خلايا TanStack لا تستضيف hooks

`cell` يُنفَّذ لكل صف، فاستدعاء hook داخله يخالف ترتيب الاستدعاء. الحل: مكوّن
صغير مُسمّى — `ActivityTypeBadge`، `SystemActorLabel`، `AssetStatusCell`،
`BookingCountLink`.

## رسائل التحقّق (Zod) — تُترجَم في طبقة العرض

مخططات Zod تعيش على مستوى الوحدة (لا يمكنها استضافة hook)، وتُعاد نفس المخططات
في الخادم عبر `parseData` وفي واجهة تطبيق الجوال. تحويل رسائلها إلى مفاتيح كان
سيسرّب مفاتيح خام إلى سجلات الخادم وإلى التطبيق المرافق.

الحل: **المخططات لا تتغيّر إطلاقاً** — تبقى رسائلها الإنجليزية هي المصدر الوحيد
للحقيقة — والترجمة تحدث عند **حدود العرض**:

```ts
// app/i18n/validation-messages.ts
export const VALIDATION_MESSAGE_KEYS: Record<string, string> = {
  "Name is required": "validation.nameRequired",
  // …103 رسالة
};

export function useValidationMessage() { … }   // نص غير معروف ⇒ يمرّ كما هو
```

ومواضع التطبيق (13 مكوّناً يعرض نص الخطأ):

| المكوّن                                                                                                                              | آلية التطبيق                       |
| ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------- |
| `forms/input`، `forms/select-with-other`، `forms/otp-input`، `forms/time-select`                                                     | `error: errorProp` ثم حلّ في الجسم |
| `shared/button`، `multi-select`، `kits/kit-selector`                                                                                 | نفس النمط                          |
| `audit/audit-selector`، `audit/audit-team-member-selector`، `asset-reminder/team-members-selector`، `booking/forms/fields/custodian` | نفس النمط                          |
| `assets/custom-fields-inputs`                                                                                                        | تغليف `getFieldError` (نقطة واحدة) |
| `advanced-filters/value-field`                                                                                                       | تغليف `useMemo` الذي يدمج الأخطاء  |

**عند إضافة رسالة تحقّق جديدة:** أضِف النص الإنجليزي الحرفي إلى
`VALIDATION_MESSAGE_KEYS`، والمفتاح المقابل إلى **كلا** ملفي الترجمة تحت نطاق
`validation`. سكربت `valcov` يفشل إن نسيت.

## صيغ الجمع العربية

14 مفتاحاً كان يُدرِج `{{count}}` بلا تصريف صار يحمل الصيغ الست العربية
(`_zero/_one/_two/_few/_many/_other`) و`_one`/`_other` الإنجليزية. مثال:

| العدد | الناتج       |
| ----- | ------------ |
| 0     | حذف الحجوزات |
| 1     | حذف حجز واحد |
| 2     | حذف حجزين    |
| 3     | حذف 3 حجوزات |
| 11    | حذف 11 حجزاً |
| 100   | حذف 100 حجز  |

⚠️ **هذا غيّر النص الإنجليزي أيضاً** (أُضيفت صيغة المفرد لكل مفتاح) — راجعه.

بقيت 35 مفتاحاً يستخدم `{{count}}` بلا تصريف عن قصد: العدّاد فيها بين قوسين
(`أرشفة (3) حجوزات`) أو يسبقه اسم الوحدة، فالتصريف لا يضيف شيئاً.

## ما يجب **عدم** ترجمته (قواعد مثبَّتة بالفحص)

- رسائل Zod ونصوص `ShelfError`/`sendNotification` داخل loaders و actions.
- `label:` في `ShelfError` — مفتاح تجميع للسجلات وSentry، ليس نصاً ظاهراً.
- القيم التي تُقارَن أو تُحفَظ: `ACTION_CONFIGS[].id` في الماسح،
  `PERSONAL_USE_JOB_TITLE` في الإعداد الأولي، مفاتيح سلاسل الرسوم.
- رؤوس أعمدة CSV في مسارات التصدير (بيانات لا واجهة).
- قوالب PDF والبريد (`app/emails/**`) — عدا إزالة اسم العلامة.

## أخطاء زمن تشغيل أُصلحت في هذه الدفعة

- **TDZ في المعاملات الافتراضية** — 12 مكوّناً كانت تكتب
  `label = t("…")` كقيمة افتراضية للمعامل بينما `const { t }` مُعرَّف داخل
  الجسم، فيقع `ReferenceError` عند كل استدعاء يعتمد الافتراضي. حُوِّلت إلى
  `label: labelProp` + `const label = labelProp ?? t("…")`.
- **`t()` كمفتاح كائن** — 152 موضعاً في 79 ملفاً حيث حلّ `t("…")` محلّ
  _مفتاح_ في كائن حرفي (خطأ نحوي أو مفتاح رسم بياني مكسور). أُعيدت كلّها
  إلى نصوص حرفية.
- **`renderEventCard`** — تستدعيها FullCalendar كدالة عادية لا كمكوّن، فاستُخرج
  شعار العدّة إلى مكوّن `KitGlyph` يستضيف الـ hook.
- **`OTP_PAGE_MAP`** — كانت تحمل نصوصاً ومكوّنات مضمّنة؛ صارت تحمل
  `titleKey`/`buttonTitleKey` مع مكوّنات فرعية مُسمّاة تستضيف الـ hook.
- **`userFriendlyKitStatus` و`formatSubscriptionStatus`** — دالتان مساعدتان
  صارتا تُرجعان مفاتيح i18n يحلّها المستهلك.
- **اقتباسات زائدة** في تسميتَي فتات الخبز `account-details.tsx` و
  `assets.import-update.tsx` (`"Account Details"` بعلامتي اقتباس ظاهرتين).

## التحقّق المطبَّق بعد كل دفعة

1. الملفان `ar.json` و`en.json` يُحلَّلان ومجموعتا المفاتيح متطابقتان (مع
   تجاهل لواحق الجمع).
2. اكتمال صيغ الجمع: العربية تحتاج الصيغ الست، والإنجليزية `_one`/`_other`.
3. تطابق متغيّرات `{{...}}` ووسوم `<1>` بين اللغتين.
4. كل مفتاح يُستدعى عبر `t("…")` أو `i18nKey="…"` موجود فعلاً في اللغتين.
5. **فحص التكامل**: لا `t()` بلا `t` في النطاق، ولا hook داخل دالة ليست
   مكوّناً، ولا `label:` مترجم في `ShelfError`.
6. تحليل نحوي لكل ملف معدَّل عبر واجهة TypeScript.
7. فحص عمق الأقواس: لا `export` داخل جسم دالة (يكشف الكتل التي أُدرجت في
   الموضع الخطأ)، ولا ملف ينتهي بأقواس غير متوازنة.
8. **حلّ المفاتيح زمن التشغيل**: تُحمَّل نسخة i18next حقيقية بالموارد الفعلية
   ويُستدعى كل مفتاح يظهر في الكود (2647 مفتاحاً) في اللغتين — لا مفتاح غير
   محلول ولا متغيّر `{{…}}` متروك.
9. تغطية خريطة رسائل التحقّق: كل رسالة Zod في الكود لها مدخل في الخريطة، وكل
   مدخل يُحَل في اللغتين والنص الإنجليزي فيه مطابق حرفياً لما في المخطط.
10. عرض صيغ الجمع عند 0/1/2/3/11/100 في العربية.

> **لا يمكن تشغيل `pnpm webapp:validate` هنا** — عميل Prisma غير مولَّد في هذه
> البيئة، و`tsc` يستنفد الذاكرة بدونه. شغّلها على جهازك قبل الالتزام.

هذه فحوص نحوية/بنيوية فقط ولا تغني عن `pnpm webapp:validate`.

## نطاقات مضافة مع مسارات عمل الهيئة

هذه النطاقات وُلدت مع الشاشات الجديدة، فهي **مترجمة بالكامل في اللغتين** منذ
لحظة إنشائها ولا تدخل في المتبقّي:

| النطاق                                             | الشاشة                                  |
| -------------------------------------------------- | --------------------------------------- |
| `assetLifecycle`                                   | لوحة مرحلة الاستلام + الاعتماد الجماعي  |
| `assetForm.lifecycle*`                             | حقل مرحلة الاستلام في نموذج إنشاء الأصل |
| `requests`                                         | صفحة الطلبات `/requests`                |
| `myCustody`                                        | صفحة الأصول في عهدتي `/my-custody`      |
| `availableAssets`                                  | صفحة الأصول المتاحة `/available-assets` |
| `nav.mySpace` / `nav.inventory` / `nav.operations` | عناوين أقسام القائمة الجانبية           |

**قاعدة للشاشات القادمة:** أي شاشة جديدة تُولد مترجمة. إضافة نص إنجليزي خام
«على أن يُعرَّب لاحقاً» تُضخّم المتبقّي وتُنتج شاشة تُترجم مرتين.

`nav.assetManagement` لم يعد مستخدماً بعد إعادة تقسيم القائمة — أُبقي في
الملفين تفادياً لكسر أي مرجع متأخر، ويمكن حذفه بأمان لاحقاً.
